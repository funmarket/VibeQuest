# Shared theme and design tokens

The shared UI package owns semantic colors in `packages/ui/src/tokens.css`. Light Daybreak and dark Night Navigator preserve the authoritative palette: background, surface, raised surface, primary/secondary text, borders, Explore blue, coral and teal. Accessible orange, Share pink and Vibe purple retain destination identity. Features use these tokens, not local palette literals. The same component tree and geometry serve both themes and hosts.

Required tokens are `--bg`, `--surface`, `--raised`, `--text`, `--muted`, `--border`, `--blue`, `--coral`, `--teal`, `--orange`, `--pink`, `--purple`, `--focus` and `--shadow`. `--coral-ink` and `--teal-ink` provide stronger foreground variants in light mode. The vivid authoritative coral/teal tokens can decorate surfaces; ordinary small text must use their ink variants. Borders are separators, not sufficient by themselves to identify a control or focus state. Focus uses the stronger blue token with an outline independent of color-only state indicators.

`ThemeProvider` owns `light | dark | system` preference and resolved `light | dark` theme. `useTheme()` returns `preference`, `setPreference` and `theme`. Its optional `hostScheme` input is passed from the application's host bridge; the UI package never imports the application or Telegram SDK. Resolution priority is explicit preference, valid launched-host hint, then operating-system preference. Invalid stored values become system. OS and cross-tab preference events update the single owner. Storage failure preserves working in-memory selection.

`themeBootstrap` is exported by the server-safe `@vq/ui/theme-policy` entry for a head script before first paint. The client `@vq/ui/theme` entry imports and reexports the same policy for compatibility; server layouts must import the policy entry directly. It reads the same `vq.theme` preference and resolution policy, writes `data-theme` and native `color-scheme`, and handles blocked local storage. The provider uses pre-paint effects to adopt persisted preference and update root presentation without creating another theme authority. The host adapter updates its scheme before paint and forwards future theme events. Preference storage contains presentation choices only, never simulated business persistence.

`--on-accent` is white in light mode and dark ink in dark mode for blue, orange, pink and purple action backgrounds. `--gold`, `--capsule` and `--capsule-text` preserve the Vibe black/gold composer in both themes. `--scrim` dims modal backdrops. Computed WCAG contrast across background/surface/raised surfaces is at least 4.63:1 for all small-text ink tokens in light mode and 6.26:1 in dark mode; action foreground/background and capsule pairs are checked separately. Raw coral/teal are excluded from the small-text claim.

Theme tests execute the bootstrap, preference resolution and simulated host events/cleanup. `tests/browser/theme-host.spec.ts` exercises host scheme updates, explicit overrides, insets, shared router back-handler cleanup and storage denial in a real browser using an explicitly simulated SDK. Browser acceptance must additionally verify startup, persistence, live OS changes and responsive screenshots. Actual Telegram-host acceptance remains a separate unverified runtime gate until tested inside Telegram.

One application shell owns header, bottom navigation, content clearance, gutters and host safe-area CSS. Feature components own only their internal layouts. CSS logical properties support Arabic RTL; theme does not own language or browsing-city preferences. No filter inversion, duplicated theme listeners, DOM relocation, geolocation prompt or feature-specific color patch is needed.
